# Studio 操作验收

范围：单用户本机方案编排、浏览与 Demo 草稿验证。

## 交互目标

首次使用者应能找到开始入口，区分查看与修改、应用与保存，并知道运行使用哪组数据。
常用路径是选择示例或打开文件、调整节点、校验并运行、保存；空白编排和部署关联保留明确入口。
复杂图的全图预览用于理解关系，选中节点后可直接放大阅读；不要求用户记住隐藏手势。
自动化通过不等于首次用户体验通过，仍需人工检查文案、信息密度与阅读效果。

## 操作路径与验收标准

| 任务 | 当前路径 | 验收标准 |
| --- | --- | --- |
| 首次进入 | 空画布 → 新建方案或导入文件 | 可见入口；顶部列表仍可打开已有方案 |
| 从示例新建 | 新建 → 从示例开始 → 选择示例 → 创建方案 | 先选择再创建；输入输出高级选择不干扰示例路径 |
| 从空白新建 | 新建 → 从空白开始 → 选择输入输出 → 创建方案 | 可分别添加多个输入输出项；不误用之前选中的示例 |
| 查看参数 | 打开 → 单击节点 | 属性直接可见且只读；详情可收起，浏览不产生修改 |
| 阅读复杂图 | 选中节点 → 放大选中节点 → 查看全图 | 可读文字和端口；缩放不修改文档；手动缩放在切换编辑时保持 |
| 设置输入输出 | 单击业务输入或业务输出 | 自动展开设置；当前构建不支持的 Converter 保留已有参数 |
| 校验 | 画布校验 | 浏览态可调用；原生诊断保留节点定位 |
| 连续调参 | 修改 → 切换节点 → 应用并继续 | 保留未完成输入；成功后切换；放弃不修改方案；撤销恢复已应用修改 |
| 处理非法字段 | 修改 → 校验 → 应用并继续 | 错误字段获得焦点，原输入保留；修正后完成原校验 |
| 保存 | 保存 → 必要时应用并继续 | 只替换 JSON；关联的 .conf 核对版本且保持原文；外部修改冲突不覆盖文件 |
| 同时保存 | 两个页签保存同一版本 | 一个成功，另一个收到冲突；成功 revision 与磁盘内容一致 |
| 命令附件失败 | 成套保存时输出目录不可写 | 文件和 revision 仍显示已保存，另行提示运行命令未生成 |
| 草稿运行 | 画布运行… → 选择示例数据 → 运行当前方案 | 打开面板不应用草稿；实际运行先应用合法修改，首条命中新规则、第二条未命中 |
| 无匹配示例 | 运行页 | 明确说明原因及配置入口，运行按钮禁用；仍可编辑和保存 |
| 结果时效 | 完成运行 → 修改或撤销 | 修改后提示旧版本；撤销回相同内容及设置恢复匹配 |
| 跨文档任务 | A 提交运行 → 打开 B → A 返回 | B 不显示 A 的样本和日志；仍在执行的任务可取消 |

## 验证方式

- 简单方案：生产 `keyword_match` 契约及 `keyword_match_rules` Profile。
- 多节点方案：`pipeline_doc_qa_rerank_cpu.json` 的临时副本，仅用于浏览和编辑路径。
- 桌面：1280×768、1366×768、1920×1080，检查浏览与编辑模式的关键按钮可达、
  页面无水平溢出、画布可用；保存截图用于人工核对布局。
- `tests/tooling/studio_editor_test.mjs` 验证快照不可变、草稿/设置变化导致过期、
  Demo 样本计数及输出纯文本渲染。
- `tests/tooling/test_pipeline_studio.py` 验证关联后的 JSON 保存、.conf 保持不变及重启后的区别，
  以及并发保存、命令附件失败、自动 Profile 匹配、忽略终止信号的子进程取消/超时回收与日志保留，
  并通过可选 `studio_browser_test.mjs` 检查新建入口、示例克隆、规则编辑、撤销/重做、
  保存（含命令附件失败提示）、修复预览、节点聚焦、I/O 参数保留、运行与结果过期。所有方案写入临时目录。
- 浏览器回归使用真实关键词 Demo 检查改动后的 `BROWSER_VIP` 命中结果及第二条未命中，
  并检查三个桌面尺寸的按钮可达性与水平溢出。水平 SVG 连线以实际路径中点点击。
- 跨文档任务和非法字段后的继续操作仍应按表中步骤人工检查；当前浏览器脚本未覆盖
  延迟任务响应下的跨文档竞态，不能据此声称该竞态已自动验收。

不以自动化推断首次使用者的发现时间，也不将关键词 Demo 成功作为真实模型效果
或目标硬件验收。浏览器组件为本地已安装工具，不增加项目依赖。
