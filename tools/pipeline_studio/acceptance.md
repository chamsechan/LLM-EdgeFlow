# Studio 操作验收记录

日期：2026-09-10。范围：单用户本机方案编排、浏览与 Demo 草稿验证。

## 复核基线

原界面已有全宽画布、节点选择、缩放、自动布局、撤销和原生校验。浏览器复核确认，
浏览时节点可以选中，但属性栏隐藏；新建位于隐藏算子栏的折叠区域；保存遇到草稿时仅
提示先应用，需要重新发起保存。运行完成后修改规则，旧结果仍显示 completed，未标记过期。
这些问题分别涉及入口发现、操作衔接与结果归属。自动化通过不等于首次用户体验通过。

## 操作路径与验收标准

| 任务 | 当前路径 | 验收标准 |
| --- | --- | --- |
| 从模板新建 | 顶部新建 → 业务契约与 Profile → 新建方案 | 一次点击展开表单；克隆的业务与节点正确 |
| 查看参数 | 打开 → 单击节点 | 属性直接可见且只读；详情可收起，浏览不产生修改 |
| 校验 | 画布校验 | 浏览态可调用；原生诊断保留节点定位 |
| 连续调参 | 修改 → 切换节点 → 应用并继续 | 保留未完成输入；成功后切换；放弃不修改方案；撤销恢复已应用修改 |
| 处理非法字段 | 修改 → 校验 → 应用并继续 | 错误字段获得焦点，原输入保留；修正后完成原校验 |
| 保存 | 保存 → 必要时应用并继续 | 显示实际目标文件；配套方案包括 JSON 与 .conf；外部修改冲突不覆盖文件 |
| 草稿运行 | 画布运行 → 运行草稿 | 状态、样本统计和输出优先可见；修改规则实际改变首条命中，第二条不命中 |
| 结果时效 | 完成运行 → 修改或撤销 | 修改后提示旧版本；撤销回相同内容及设置恢复匹配 |
| 跨文档任务 | A 提交运行 → 打开 B → A 返回 | B 不显示 A 的样本和日志；仍在执行的任务可取消 |

## 验证方式

- 简单方案：生产 `keyword_match_v1` 契约及 `keyword_match_rules` Profile。
- 多节点方案：`pipeline_doc_qa_rerank_cpu.json` 的临时副本，仅用于浏览和编辑路径。
- 桌面：1280×768、1366×768、1920×1080，检查浏览与编辑模式的关键按钮可达、
  页面无水平溢出、画布可用；保存截图用于人工核对布局。
- `tests/tooling/studio_editor_test.mjs` 验证快照不可变、草稿/设置变化导致过期、
  Demo 样本计数及输出纯文本渲染。
- `tests/tooling/test_pipeline_studio.py` 验证服务会话内配套保存范围与重启后的区别，
  并通过可选 `studio_browser_test.mjs` 运行上述浏览器路径。所有方案写入临时目录。
- 浏览器回归使用真实关键词 Demo 检查改动后的 `SAVED_BROWSER` 命中结果，使用延迟
  的任务响应确定性重现跨文档竞态。样本正确性与页面流程分别检查。

本轮不以自动化推断首次使用者的发现时间，也不将关键词 Demo 成功作为真实模型效果
或目标硬件验收。浏览器组件为本地已安装工具，不增加项目依赖。
