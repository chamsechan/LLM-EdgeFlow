# 方案开发者试用与生产验收计划

- 整理日期：2026-09-07；原规划日期：2026-09-06。
- 状态：工程接入路径已有验证记录；开发者试用、具体业务效果与目标环境验收仍待完成。
- 范围：承接原《面向大模型方案开发者的架构定位与实施规划》的未完成事项，保留用户诉求和验收依据。

## 1. 用户诉求与实施边界

框架面向大模型方案开发者，日常工作是组合节点、实现缺失算法、转换平台输入输出，
并通过统一 Demo 验证方案。

| 已确认诉求 | 验收时关注什么 |
| --- | --- |
| 已有 Node 可以连线构成方案 | 沿用已注册业务契约时，通过 Pipeline/Studio 完成配置与运行 |
| 缺失算法允许在 Node 中实现，也能跨方案复用 | 领域算法有明确输入输出，不绑定某份 Pipeline 的实际黑板键 |
| Adapter 对接完整 C ABI 输入输出契约 | 请求字段提取与响应组装在 SDK 内完成，直接调用 C ABI 可独立验证；C 载体相同也要检查载荷协议 |
| 使用一个通用 Demo | Demo 构造完整宿主载体并展示 SDK 结果，新业务协议转换留在 Adapter；复用执行、参数和结果输出路径 |
| 降低作者门槛并保持框架整洁 | 记录实际修改范围、重复代码、首次跑通耗时与求助原因 |
| 接受仓库内源码扩展与重新编译 | 优先验证现有静态注册与构建路径 |
| custom Node 按操作集中组织 | 领域算法放在统一目录，能够用于多个方案 |

当前职责与接口见[架构设计](../architecture.md)、[开发者扩展指南](../developer_guide.md)
和[自定义 Node 源码指南](../../src/custom_nodes/README.md)。这些入口维护现行规则，
本计划只跟踪试用和验收。后续简化需由实际重复成本驱动；动态插件、多模型支持等建议
不自动成为待交付承诺。新增能力或公共契约遵循 [CONTRIBUTING](../../CONTRIBUTING.md)。

## 3. S4：开发者试用

邀请未维护过 Core 的方案开发者，使用对应[任务入口](../README.md#按任务开始)
独立完成实际需要的任务。先采集基线，再设置团队接受的时间预算。

| 任务 | 通过条件 |
| --- | --- |
| A：组合已有能力、调整提示词或切换兼容模型 | 沿用同一合法业务契约，通过配置完成原生校验和 Demo 样本运行 |
| B：实现缺失的领域算法，并用于第二个方案 | 主要改动在 custom Node、构建登记、测试和配置；复用注册类型，无复制算法文件 |
| D：给同一类型的两个实例配置初值并定向下发 Control | 只有目标实例的输出改变；非法更新保持旧值；输出和诊断可关联请求与实例 |
| C：接入新的平台结构 | 改动集中在接入适配层和必要的 Demo 转换，模型与调度代码不感知平台字段 |
| 定位并修复失败 | 作者能够定位非法端口、参数或模型绑定；运行错误能关联节点与请求 |

每项任务记录：代码基线、任务与预期结果、首次跑通耗时、修改文件、求助次数、
失败原因、输出证据及待修复问题。未参与的任务记为未覆盖，不从另一项成功推断通过。
记录附在本文对应任务下；修复使用现有责任套件，避免为每轮试用再创建实施计划和复审报告。

## 4. S5：具体方案生产验收

每个拟上线方案预先约定目标数据集、效果指标、设备性能、输出容量和稳定性要求。
使用[模型、构建与效果验收指南](../VERIFIABLE_SELECTION.md)准备可复核记录；
工程 Smoke 通过不能替代这些验收。

- [ ] 选择真实模型与部署组合，记录资产、配置、工具和数据集基线。
- [ ] 执行约定的业务效果评测，记录失败样本与未覆盖场景。
- [ ] 在目标设备验证性能、容量、生命周期与稳定性。
- [ ] 完成宿主接入验证，并明确最终通过范围和限制。

涉及公司内部 SDK 时，按 [RFC-0029](../rfcs/0029-external-readiness-and-intranet-sdk-migration.md)
在项目迁入授权内网后开展真实集成。当前外部工作区只准备中立扩展入口。

所选试用任务和每个拟上线方案均有对应证据，未完成项已明确归属与范围后，更新本文状态。
