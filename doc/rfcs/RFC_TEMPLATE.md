## 1. 问题与范围

说明具体触发场景、现有能力缺口、预期行为和范围边界；需要时注明代码基线。

## 2. 决策与权衡

描述采用的方案、选择原因、主要替代方案和代价。只填写实际受影响的职责：
接入适配层 / Integration、流程编排层 / Orchestration、
能力节点层 / Capability Nodes、模型执行层 / Model Execution；纯工具或治理变更注明其范围。

按需补充关键接口或简图，重点交代跨层依赖及必须保持的不变量。
涉及所有权、生命周期、并发、错误传播或性能时，说明对应约束。

## 3. 兼容与迁移（按需）

说明公开接口或持久配置的变化、受影响消费者、迁移步骤与回退边界。
取代旧决策时明确对应 RFC 和具体范围。

## 4. 验证与完成条件

列出能够证明本次行为和不变量的最小测试及可观察结果，优先扩展已有责任套件。
按风险补充真实模型、硬件、兼容性或性能验证，明确未覆盖范围。
交付门禁和状态更新遵循 [CONTRIBUTING.md](../../CONTRIBUTING.md#6-run-one-canonical-delivery-gate)。

## 5. 实施与最终结果

按复杂度列必要里程碑。完成时记录最终决策、验证基线与结果、遗留边界及现行指南链接。
独立评审确有额外证据时链接原始记录；常规进度直接更新本文，不另写重复的接续计划。
