# RFC 0074：删除旧配置的专用处理

- **RFC 编号**：0074-current-config-only
- **创建日期**：2026-09-23
- **文档状态**：Completed
- **关联分支**：`refactor/current-config-only`
- **目标版本**：投产前
- **负责人 / 作者**：LLM-EdgeFlow maintainers
- **关联决策**：补充 RFC-0073，删除旧名字的专用迁移提示；配置入口与运行契约不变。

## 1. 范围与决策

旧字段此前已不可用，但外部根业务名和 Profile 业务选择还存在按旧名字分支的报错代码。
本次删除这些分支，只按当前声明的字段校验；未知字段与未知参数统一拒绝，不做别名、转换、
回退或静默忽略。不新增作者需要配置的字段、命令或格式，公共 SDK ABI 保持 9。

接入适配层维护外部 Pipeline 结构，由 Core 结构投影并加入 deployment，解析器与 Schema
复用该结构。内部派生业务身份继续用于注册边界验证，不作为外部可填写字段。
Profile 当前字段在 Demo 所属的一份内部字段列表声明，原生构建嵌入该列表，Python 工具
读取同一来源，替换各处旧名黑名单。列表不是用户配置；既有字段类型、范围及默认值保持。
当前文档只讲现行用法，历史 RFC/Changelog 保留当时记录；测试可保留旧名字作为非法输入。

## 2. 验证与完成条件

- 任意未知 Pipeline 根字段（含 JSON Pointer 转义键）、Profile 字段和 Demo 参数均拒绝。
- 已删除的名字不能被接受或静默丢弃；有效配置、默认输出容量和 Profile 运行保持。
- CLI、Schema、Demo、Studio、Recipe 使用相同当前字段定义，不维护旧名字处理分支。
- 独立检查及 CONTRIBUTING 统一门禁通过；真实模型与未启用后端不在本次范围。

## 3. 实施结果

- 删除运行实现中的旧名字专用判断、提示和回退；保留现行内部业务注册信息。
- 六个 Profile 消费入口共用九个当前字段；生成头仅在 Demo 与两个 CLI 构建目标私有可见。
- 原生聚焦 6 组 CTest 通过；Studio 100 项中 99 项通过、1 项浏览器测试未配置而跳过，
  Recipe 23 项通过。本次未修改前端交互。
- 关键词配置实际运行 4 条，请求 ID、状态及两次命中/两次未命中的结果正确；普通与转义
  未知根键均被拒绝。独立审查无剩余阻断项。
- 最终门禁采用 `LLM_EDGEFLOW_JOBS=6 ./scripts/run_all_tests.sh`；完成状态与最终代码一并
  提交本地门禁验证，失败恢复实施状态。SDK ABI 保持 9，无远程交付。
