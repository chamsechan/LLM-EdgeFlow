# 错误码与日志

项目维护两套错误码：框架码定义在 `include/contracts/error_codes.h`，当前平台对外码
定义在 `include/platform_mock/error_codes.h`。内部整数接口沿用 `int`。成功为 0，失败使用
`llm_edgeflow::error::k...`，同一值只有一种含义。Core、Node、Model、Backend 和 Adapter
内部使用框架码，不引用平台错误码。Operator 协议壳是唯一的平台错误映射边界。
公开 C 接口（Operator 函数表和 AlgBase 日志接口）沿用各自的平台或文档化返回约定，
不返回框架码。日志接口的约定由 [日志](../logging.md) 维护。

框架码表同时提供 `ErrorCodeName`，供结构化诊断、CLI 和日志使用。诊断的字段路径、
节点/模型名及原因继续单独传递。不得用统一分类代替具体原因。Studio 的错误名称引用
同一张表，HTTP 状态仍由 HTTP 接口决定。厂商状态留在 Backend 中转换，原始原因保留
在诊断中。

## Operator 失败分类

公共失败出口分两步得到返回码：

1. **共享层判定类别。** [operator_failure_category](../../src/adapter/operator/operator_failure_category.h)
   定义失败阶段、阶段名称、Control 阶段转换和诊断描述，并由“失败阶段 + 内部码”判定类别。
   该层不包含平台头。
2. **协议壳映射平台码。** 每个壳只维护“类别 → 平台码”表，表项使用平台头符号，不写数字字面量。
   mock 壳的表在 [operator_error_mapping.cpp](../../src/adapter/operator/mock/operator_error_mapping.cpp)。

类别固定为 10 项：成功、无效句柄、参数非法、输入非法、输出容量、业务不支持、注册冲突、
控制不支持、标准异常、未知。平台可以让多个类别使用同一码值，框架不因此合并类别。

判定先处理成功码，再按失败阶段分类：

| 失败阶段 | 判定规则 |
| --- | --- |
| 创建准备 | 业务不支持、注册冲突、标准异常、未知异常各有专门分支；其他失败码归参数非法 |
| Pipeline 执行、Control 节点更新 | 所有失败码归未知 |
| Control 请求 | 所有失败码归参数非法 |
| Control 不支持 | 所有失败码归控制不支持 |
| 运行时 | 按内部码逐项分类；其他失败码归未知 |

未声明的内部码按所在阶段兜底，不能统一归未知。内部码只用于诊断，不能直接作为公共返回值。
Warning/Error 由类别和内部码决定：调用方可修正的拒绝记 Warning，分配、池损坏、模型物化和
Node 创建/初始化失败记 Error。

## 实施与验收边界

1. 从框架码表选择与失败原因对应的错误码。
2. 新增内部码时，在共享层按错误含义归入类别。不要仅按数值相等建立映射。
3. 填写具体原因和诊断上下文。
4. 在测试中核对内部码、类别、平台码、诊断内容和日志等级。

分类规则由[共享层分类测试](../../tests/unit/operator/test_operator_failure_category.cpp)覆盖。
公共入口行为由[壳无关一致性套件](../../tests/contract/operator_shell/)覆盖：场景固定期望类别，
期望平台码从所选壳的错误码镜像清单读取，每次带状态的公共调用都检查返回值属于登记集合且等于
期望类别的登记值。清单每个类别记录平台符号名、独立写定的数值、核对状态和依据；核验要求
每个类别恰有一项、壳内映射与登记值一致、失败码与已声明内部码不相交、成功码为 0。
mock 清单全部标为“外网占位”。真实值只能在授权内网按已确认的宿主契约登记，
不能根据被测返回值修改清单。

集合检查只能发现集合外的透传值。内部码恰好等于期望平台码时，精确比较也无法识别透传，
因此仍需保留分类测试和公共失败出口的映射路径审查。套件通过不证明所有路径的数据流。

修改错误处理时，保留输出清理、来源编号、Control 回滚、输出池生命周期和异常屏障。
测试应覆盖主动失败、标准异常、未知异常、配置错误和运行时错误。
执行默认门禁。若涉及非默认 Backend，还需构建并验证对应测试。真实推理需要权重和运行环境。

## 日志职责

在错误产生处填写具体原因。在具有完整调用上下文的边界记录日志。
直接转发错误的函数不重复记录。独立入口没有上层日志时，由该入口记录。
平台映射日志包含框架错误名称、内部码、平台码和操作。不要记录完整请求、模型输入或凭证。

沿用 `edgeflow/log.h` 的六级宏：

| 等级 | 用途 |
| --- | --- |
| `ALG_LOG_FATAL` | 运行实例无法继续服务的致命故障 |
| `ALG_LOG_ERROR` | 执行、资源、异常或内部约束失败 |
| `ALG_LOG_WARNING` | 输入/配置被拒绝、可恢复异常或降级 |
| `ALG_LOG_INFO` | 初始化、加载、配置切换等生命周期 |
| `ALG_LOG_DEBUG` | 阶段、数量、容量等排查上下文 |
| `ALG_LOG_VERBOSE` | 按需开启的逐项、逐批次细节 |

按调用场景选择日志等级。错误码表不设置日志等级。
关闭日志后，调用者仍可读取错误诊断。
