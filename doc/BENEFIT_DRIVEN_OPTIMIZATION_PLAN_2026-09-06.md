## 3. A：输出类型复用，先证明收益

### 3.1 最小试点

仅选现有 `keyword_out` 与 `entity_out`。两者都包含一个池化字符串，但标量字段不同，适合检验公共操作能否复用且保持类型差异清楚。

1. 记录两个类型中分配、重置、容量声明与清理登记的位置，作为试点前的比较对象。
2. 优先扩展当前文件中的小型类型安全 helper，复用确实相同的操作；保留每个类型的容量与字段含义。标量字段差异仍显式表达。
3. 保持注册接口、现有 C/Operator 布局、错误行为及内存归属不变。暂不把多字符串、数组或 metadata 类型纳入试点。
4. 比较两个类型的最终代码与公共 helper，计算总维护量；不能只看原注册函数缩短了多少行。

### 3.2 收益验收

只有同时满足以下条件，才保留试点并考虑扩大到其他同构类型：

- 至少一种原先在两个类型中重复实现的行为变为一处实现，另一类型直接复用。
- 修改该共同规则只需修改公共实现；类型差异仍能在各自注册处直接读懂。
- 在临时 diff 中用一个现有类型演练字段调整，所需同步修改的位置不增加；不为演练引入生产新类型或改变真实字段。
- 计入新增 helper 后，未引入新的动态分配、运行时字段查找或多层转发来换取少量行数下降。
- 对外可观察行为不变，相关测试通过。

若必须引入通用反射、字段 DSL、大量宏或深继承才能复用，或者每个类型仍需复杂特化，则结束试点，保留原本清楚的显式实现。单纯拆文件、搬移注册内容不作为收益。

### 3.3 回归范围

复用现有 [ValueRegistry 测试](../tests/unit/operator/test_operator_value_registry.cpp) 和 [OutputPool 测试](../tests/unit/operator/test_operator_output_pool.cpp)，仅补齐受改动影响而尚未覆盖的行为：

- 默认和自定义字符串容量、容量拒绝及内存预算与原实现一致。
- 写入后归还、再次取出时，标量与字符串内容正确重置，嵌套缓冲区地址和容量保留。
- 分配失败时正确清理已分配对象，不发布半成品，不重复释放。
- 池归还和复用过程不新增动态分配；相关业务端到端输出保持一致。

测试预期由外部可观察契约独立给出，不从生产 helper 的字段描述自动生成，以免生产代码和测试同时遗漏字段。已有覆盖充分时无需为 helper 本身另建测试。

分配与重置路径发生变化时，使用现有 Sanitizer 构建机制对受影响套件做 ASan/UBSan 验证；泄漏验证需显式开启并记录结果，不能把默认关闭泄漏检测的运行记成泄漏验证通过。

## 4. B：测试复用，保留场景表达力

只从 `test_operator_api.cpp` 中至少三个重复准备配置的常规场景开始，例如关键词、文档问答、实体提取。

1. 在现有 fixture 内提供一个公共默认配置构造入口，场景只指定配置文件及真正不同的参数。
2. 明确字符串、路径和输入缓冲区的所有者，使 C 指针在使用期间保持有效；避免 helper 返回指向局部字符串的指针。
3. 仅在输入结构和断言含义相同的场景中使用参数化。不同模态、不同生命周期场景保持独立测试。
4. 只有多个场景确实重复完整的正常句柄生命周期时，才提取相应支持对象。验证销毁时机、未释放输出、失败 Create 等场景继续显式管理资源。

收益验收：

- 选定场景的公共默认参数从至少三处维护变为一处；修改默认值无需逐例同步。
- 测试主体仍能直接看见业务输入、场景差异和关键断言，失败可定位到具体场景。
- 保存试点前后的用例及关键断言对应关系；不减少异常边界、所有权、并发和输出容量覆盖。
- 支持代码留在测试侧，优先留在本文件；未出现第二个实际使用方时不建立跨套件公共库。

若 helper 需要大量布尔开关、隐藏错误检查或生命周期步骤，停止抽取。测试已经参数化的区域不重复改造；测试行数下降不构成覆盖保持的证据。

## 5. C：文档按需收敛及明确暂缓项

执行 [CONTRIBUTING.md](../CONTRIBUTING.md) 已有规则：局部机械重构、测试改进通常无需 RFC；历史 RFC 保留原始上下文；当前规则在权威入口维护，其他位置使用链接。可执行能力和字段查询 Catalog，不新增手工同步清单。

本计划是带基线的任务记录，不成为新的架构规范。实施结果直接更新本文对应任务状态或放入交付说明，不为每个小步骤再生成一份评审报告。

| 暂缓事项 | 当前理由 | 重新考虑的触发条件 |
| --- | --- | --- |
| 全量重写或删除历史 RFC | 历史篇幅不等于持续维护成本，改写会损失决策上下文 | 当前导航实际误导使用者时，修正入口或补充后继链接 |
| 拆分所有大文件、调整四层目录 | 尚未证明能降低一次变更的搜索与修改成本 | 具体需求反复同时修改不相关职责，已有实际变更证据 |
| 通用 Adapter 框架、字段 DSL、代码生成器 | 目前仅证实少量机械重复，工具链成本可能超过节省 | 简单 helper 无法满足多个真实接入需求，再做成本比较与 RFC |
| 删除 C ABI 校验、异常屏障或池生命周期处理 | 这些承担明确外部契约，不能用行数目标替代 | 外部契约确需改变，按正式兼容性决策处理 |
| 为减少拷贝改写完整请求数据路径 | 本次未测量拷贝耗时及端到端影响 | 在真实工作负载中定位到显著瓶颈后，另行设计与性能验收 |
| 全库测试去重、新增测试框架或大规模归并套件 | 尚未识别跨全库的必要收益 | 有具体维护故障或反馈时间证据，按责任套件逐项处理 |
| 提前改造内网 SDK 接入 | 当前缺少授权环境和真实契约 | 按 [RFC-0029](rfcs/0029-external-readiness-and-intranet-sdk-migration.md) 在内网阶段实施 |

## 6. 实施、验证与完成条件

A、B 各自形成小型可独立审查的变更，避免混入业务功能或全库迁移。局部实现不改变公共契约；若调查中发现必须改变所有权、跨层职责或外部兼容行为，按贡献规范重新分类并先建立 RFC。

开发期间复用现有构建目标和测试入口，先按实际改动选择受影响套件。例如 A 可使用：

```bash
cmake --build build --target edgeflow_test_adapter_runner
ctest --test-dir build --output-on-failure \
  -R '^(OperatorValueRegistryTest|OperatorOutputPoolTest|OperatorApiTest|OperatorGoldenTest)$'
```

B 以 `OperatorApiTest` 为主要验证范围。每个独立交付变更完成后，运行一次统一本地门禁 `./scripts/run_all_tests.sh`；不要在它前后重复完整 CTest 或格式门禁。所需 Sanitizer 属于 A 的专项证据，不替代统一门禁。

交付说明只需提供：实际修改范围、共同规则修改点的前后对比、关键行为覆盖及测试结果、是否值得扩大。若实际收益不成立，结束该项并记录结论，允许没有生产代码变更。

本计划不承诺推理加速、缺陷率下降或固定比例的代码缩减。最终应能证明的是：同一规则需要修改的位置更少，关键行为继续可验证，新增抽象的维护成本小于它消除的重复成本。

试点暴露并修复一个现有重置遗漏：`CompanyOperatorKeywordOutput::status_code` 写入 `-42` 后归还池，再次取出仍为 `-42`。扩展原有 `AddressReuseAndResetContract` 后先在旧实现上复现失败，随后补齐状态码清零。该修正恢复内部池槽的初始状态；Operator bridge 本已逐次写入业务状态码，公共结构布局、容量、错误码约定和所有权未改变。

补充覆盖仅落在现有测试文件：实体输出默认/自定义容量下的填满缓冲区、地址复用、标量与字符串重置、归还/取出零分配，以及两类输出的容量默认值、上界与载荷预算。已有全部输出类型逐分配点失败回滚用例继续复用。

验收证据：

- 默认构建下 `OperatorValueRegistryTest`、`OperatorOutputPoolTest`、`OperatorApiTest`、`OperatorGoldenTest` 四个套件通过。
- 对比基线源码：`OperatorApiTest` 的 29 个用例名称及顺序不变；三个选定场景从句柄创建开始的测试主体逐字一致，分别保留 10、8、8 个断言。
- 使用临时独立程序、基线/当前注册实现和已有分配失败支持，在本机 GCC/libstdc++ 下逐分配点对比：关键词每块分配均为 5 次，实体每块均为 4 次，重置均为 0 次；完整 Registry 构造分配由 435 次变为 434 次。该实验仅验证未增加本机分配开销，不构成跨平台或端到端性能承诺。
- 计入新增 helper 后，生产注册文件为 1,087 → 1,083 行，集成测试文件为 2,014 → 2,011 行。对应单元测试增加 94 行用于验证上述行为；本轮保留依据是维护点减少和遗漏得到修复。
- ASan/UBSan 与泄漏检查：使用现有 CMake Sanitizer 选项构建 `build-sanitizers-adapter-cleanup`，启用 `address,undefined` 和 `ASAN_OPTIONS=detect_leaks=1:abort_on_error=1`，UBSan 使用仓库现有 suppression 文件并在错误时停止。四个受影响套件通过，实际 62 个用例通过；专项构建关闭真实推理 Backend，两个 CrossRerank 用例因未启用 ONNX 跳过，这两个用例已在默认构建的针对性回归中通过。无 ASan、UBSan 或泄漏报告。
- 统一本地门禁：`./scripts/run_all_tests.sh` 通过，89 项 CTest 全部成功；本轮末次门禁耗时 23 秒，仅作执行记录，不作为性能改善结论。
